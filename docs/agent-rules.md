# Long Memory Studio: AI 운영 브리핑

이 문서는 `GET /api/agent/brief`의 앞부분이다. 새 작업(또는 `clear` 직후) 첫 단계로 읽고, 아래 "지금 상태"와 "다음 할 일"을 따라 진행한다.
자세한 절차는 Aside 스킬 `longform-studio`(전체), `longform-flow-veo`(Flow), `longform-gpt-images`(키프레임)에 있다.

## 시작
1. `GET /api/agent/brief` (이 문서 + 실시간 상태). 편 하나를 볼 때는 `GET /api/episodes/<ID>/summary` (전체 조회는 크다).
2. REPL 헬퍼: `eval(await (await fetch('http://127.0.0.1:5178/api/agent/helpers.js')).text()); await lmsAttach();`
3. 기능 목록: `GET /api`. 서버 코드를 grep하기 전에 먼저 본다.

## 상시 규칙 (사용자 결정)
- 답변은 한국어, em dash 금지. 시청·좋아요 같은 알고리즘 작업 금지. 결제·요금제 변경, 공개 전환(예약 제외)은 묻는다.
- 승인 위임(2026-11-10): G1/G2/G3는 Aside가 권장안대로 정하고 `{"by":"aside","note":"근거"}`로 기록. Flow 크레딧과 비공개 업로드는 사전 승인.
- 대본은 줄이지 않는다(단어 상한 없음). 8분을 넘으면 분할. Ava (Premium) rate 115, lineGapSec 1.0.
- 그림: 사람은 뒷모습·실루엣만(얼굴·옆모습 금지), 하나님은 손이나 빛, 이미지 속 글자 금지, 유혈·시신 금지.
- 여러 주제(2026-11-12): 주제 = 시리즈. 주제마다 다른 값(표기, 재생목록, 원문 출처와 인용·번역 규칙, 설명 꼬리말, 쇼츠 문구·해시태그, 목소리, Flow 프로젝트)은 시리즈 프로필에 있다. 에피소드를 다루기 전 `GET /api/episodes/<ID>/profile`, 시리즈 전체는 `GET /api/channel`. 새 주제는 `POST /api/series` 또는 `node scripts/new-series.mjs` (스킬 longform-studio의 Series 절). 스크립트에 주제별 문구를 하드코딩하지 않는다.
- 영상: Omni 1.2 Flash 720p → 1080p 업스케일, x1, 8초. 작업 생성은 `node scripts/mkveo.mjs <ID>` (소용돌이 금지 문구 기본).
- Flow (2026-11-12 사용자 지시): 모든 UI 동작 사이에 3.00~5.00초 랜덤 대기(0.01초 단위). 완료를 기다리지 않고 5건씩 연속 제출 → 타일 확인. REPL `const L = await pacedList('<ID>')` 후 `await pacedNext(L)` 반복, 5건마다 `pacedCheck('<ID>')`. 결과: 11/12에 약 40건까지 차단 없음(이전엔 약 10건), 40번째쯤 다시 차단 → 한 번에 35건 안팎으로 끊는다. '비정상적인 활동'이 뜨면 `POST /api/flow/block` 후 멈추고 2시간 이상 뒤 1건만 재시도. 그 밖의 우회 시도 금지.
- 수집: REPL `collectShot(job)`을 `done:true`가 나올 때까지 반복 호출(한 번에 90초 이내, 진행 상태를 저장해 이어서 함) → 돌려준 `node scripts/flow-ingest.mjs …` 명령을 Bash로 실행(앱 작업 완료까지 자동). 채택 전에 `clipSheet()`로 검수.
- 작업 상태: `done`과 `cancelled`는 끝이다(다시 승인·취소하면 409). 샷을 다시 만들 때는 `node scripts/mkveo.mjs <ID> <shot>`으로 새 작업을 만든다. 같은 파일로 complete를 다시 보내면 아무것도 바뀌지 않는다(`alreadyDone`). 제출이 안 된 작업은 `freshOne`이 `approved`로 되돌린다.
- YouTube: 하루 업로드 최대 10편. 업로드 탭은 전송 100%와 "비공개 저장"을 확인하기 전에 이동 금지. 공개 예약은 하루 1편, 뉴욕 06:00, EP 순서.
- EP 순서 규칙(사용자, 2026-11-13): 롱폼과 쇼츠는 EP 순서대로 올리고 공개한다(1 → 2-1 → 2-2 → 3 ...). 채널 동영상·Shorts 탭은 공개 시각 최신순이고 소유자가 순서를 바꿀 수 없으며, 비공개→공개 전환으로도 자리가 바뀌지 않는다. 여러 편을 동시에 공개할 때(예약이든 즉시든)는 EP 순서대로 1분씩 간격을 둔다(예: 2-1 06:00, 2-2 06:01, 3 06:02 뉴욕). 즉시 공개도 한 편씩 1분 간격으로 전환한다. 쇼츠는 한 편씩 업로드 후 공개하고, 해당 롱폼보다 먼저 공개하지 않는다. 순서가 어긋나면 사용자에게 알리고, 삭제는 사용자 결정이다.
- 자막: 수동 영어는 "영어" 행에 게시. 자동 영어 자막은 업로드 때 1회 삭제 시도, 다시 생기면 그대로 둔다. 자막 옵션은 "자동 자막" 행 것만 누른다.
- 보관: proxy → index → done(스냅숏) → evict 순서. 동기화 안 된 파일은 evict 실패가 정상이니 나중에 재시도.
- 막힘은 숨기지 말고 기록: `PATCH /api/episodes/<ID>/blocker {reason, until}`.

- 로컬 정리(사용자 규칙 2026-11-12): 영상(롱폼·쇼츠) 작업이 끝나면 로컬에 남는 폴더가 없게 한다. 에피소드 보관 뒤, 쇼츠 묶음 뒤, 세션 종료 전에 `node scripts/cleanup-local.mjs` (앱 out/ 임시본, 세션 tmp의 flow·yt2 업로드 복사본 삭제, 보관된 편의 Drive 캐시 비우기; 15분 안에 바뀐 것은 건드리지 않음). 쇼츠 빌드는 성공하면 out/shorts 복사본을 스스로 지운다. 결과물은 Drive에만 둔다.

## 설계 의도 (사용자 확인 2026-11-11, 검토에서 문제로 지적돼도 바꾸지 않는다)
- Flow 영상 작업의 크레딧 승인은 자동이다(`mkveo.mjs`가 만들면서 승인). 영상 품질이 크레딧보다 중요하고, 검수에서 별로인 클립을 바로 다시 만들기 쉽게 하려는 구조다. 편당 크레딧 상한이나 추가 승인 단계를 넣지 않는다.
- 승인자·실패 원인·환불 같은 기록의 정확도를 높이는 작업은 하지 않는다(사용자: 굳이 필요 없음).
- 제출 간격과 차단은 서버가 강제하지 않는다. `freshOne`이 제출 전에 `/api/flow/plan`을 읽고 스스로 멈추는 수준으로 충분하다.

## 세션 안전
- 에피소드가 바뀌면 `clear` 또는 새 작업. 상태는 앱·스킬·헬퍼에 있으니 잃는 것이 없다.
- 이미지 검수 시트를 base64 data URL로 만들지 않는다(`sheet()`는 로컬 서버 5199 사용). 큰 출력은 파일로 저장하고 필요한 부분만 읽는다.
- 이전 세션 기록을 수천 건 단위로 훑지 않는다(데몬 재시작 2회).
- 쇼츠/릴스(2026-11-12): 롱폼의 기존 클립·키프레임·내레이션만 재사용(Flow 금지). 스킬 `longform-shorts`. `node scripts/subject-map.mjs <ID>` → `node scripts/short-build.mjs --init <ID>` → short.json → `--dry` → 빌드. 액자형 레이아웃, 좌우 이동 금지, 공개 전환은 사용자 확인.
